# データソース一覧への削除ボタン追加 — 要求定義

| 項目 | 内容 |
|---|---|
| 開発タイトル | connections-delete-button |
| 作成日 | 2026-09-29 |
| Issue | [#36](https://github.com/sugimomoto/KintoneExternalAppCDataSample/issues/36) |
| 前提ブランチ | `fix/34-oauth-token-persistence` ([#35](https://github.com/sugimomoto/KintoneExternalAppCDataSample/pull/35)) の上に積む |
| 目的 | データソース一覧から接続を削除できるようにし、かつ参照中の接続を消して連携を壊す事故を防ぐ |

---

## 1. 背景

### 1.1 現状の実装

| 箇所 | 内容 |
|---|---|
| `web/views/ConnectionsView.kt:88` 操作列 | 「接続テスト」「編集」のみ。**削除ボタンなし** |
| `web/routes/ConnectionsRoutes.kt:147` `POST /connections/{name}/delete` | **既存**。`deleteSharedJdbcConfig` → `/connections` へリダイレクト。確認も参照チェックも無い |
| `config/SqliteConfigSource.kt:158` `resolveJdbc` | `jdbc_ref` が解決できないと `ConfigParseException` を投げる |
| `config/ConfigSource.kt:39` `sharedJdbcRefOf` | 連携が参照しているデータソース名を返す。既定実装は `null` |
| `web/views/DeleteConfirm.kt` | #8 で作った確認メッセージ生成。`escapeJsString` を持つ |

### 1.2 課題

1. **一覧から削除できない**
   登録したデータソース接続を消すには DB を直接触るしかない。検証用に作った接続
   (`SalesforceOAuth` 等) が残り続ける。連携一覧 (`/syncs`) には #8 で削除ボタンを
   追加済みで、データソース一覧だけ取り残されている。

2. **参照中のデータソースを削除すると連携が壊れる**
   `tables.jdbc_ref` に外部キー制約が無く、削除時の参照チェックも無い。参照中の接続を
   消すと、その連携の `loadTableSet` が `ConfigParseException` で失敗して起動できなくなる。
   **削除ボタンを足すだけでは、連携を壊す動線を UI に増やすことになる。**
   現在 `jdbc_ref` を持つ連携は 0 件（全連携が inline JDBC）なので実害は出ていないが、
   共通接続を使い始めた時点で踏む。

3. **確認ダイアログが無い**
   既存の削除ハンドラは無条件に削除する。非可逆な操作なので #8 と同様に確認を挟むべき。

## 2. 目的

データソース一覧から接続を削除できるようにする。ただし**参照中の接続は削除させない**ことで、
連携を壊す動線を作らない。

## 3. スコープ

### 3.1 今回実装する機能

| ID | 機能 | 内容 |
|---|---|---|
| F-1 | 一覧への削除ボタン追加 | 操作列に「削除」ボタンを追加し、`POST /connections/{name}/delete` に送信する |
| F-2 | 削除確認ダイアログ | JS `confirm` で確認する。接続名を含め、`escapeJsString` でエスケープする |
| F-3 | 参照チェック | 削除前に全連携の `jdbc_ref` を走査し、参照中なら削除を中断する |
| F-4 | 参照元の提示 | 削除できなかった場合、どの連携が参照しているかを画面に出す |

### 3.2 今回実装しない機能 (スコープ外)

| 項目 | 理由 |
|---|---|
| `jdbc_ref` への外部キー制約の追加 | 既存 DB のマイグレーションが必要。アプリ層のチェックで先に動線を安全にする |
| 参照中の連携もまとめて削除するカスケード | 連携の削除は Agent コンテナの停止まで伴う。データソース削除の副作用としては影響が大きすぎる |
| 詳細画面 (`/connections/{name}`) への削除ボタン追加 | 一覧に付けば動線は足りる。#8 では逆に詳細画面の重複フォームを一本化した |
| CSRF 対策 | Web UI 全体に仕組みが無く、このボタン単独で入れても不完全（#8 と同じ判断） |
| 削除完了のフラッシュメッセージ | 現状の Web UI にトーストの仕組みが無い（#8 と同じ判断） |

## 4. ユーザーストーリー

| ID | ストーリー |
|---|---|
| US-1 | デモ環境を構築する担当者として、検証用に作ったデータソース接続を一覧から削除したい。DB を直接触らずに片付けたいため |
| US-2 | デモ環境を構築する担当者として、連携が使っているデータソースを誤って削除できないようにしてほしい。削除すると連携が `ConfigParseException` で起動できなくなり、原因が画面から分からないため |
| US-3 | デモ環境を構築する担当者として、削除できなかったときにどの連携が邪魔しているか知りたい。先にその連携を消せば削除できると分かるため |

## 5. 受け入れ条件

| ID | 条件 |
|---|---|
| AC-1 | データソース一覧の各行の操作列に「削除」ボタンが表示される |
| AC-2 | 削除ボタンを押すと確認ダイアログが出る。ダイアログには接続名が含まれる |
| AC-3 | 確認ダイアログでキャンセルすると何も削除されず、一覧画面に留まる |
| AC-4 | OK すると `POST /connections/{name}/delete` が実行され、一覧から消えている |
| AC-5 | `jdbc_ref` で参照している連携がある場合は**削除されず**、設定が残っている |
| AC-6 | 削除できなかった場合、参照している連携名が画面に表示される |
| AC-7 | 複数の連携が参照している場合、すべての連携名が表示される |
| AC-8 | シングルクォートを含む接続名でも確認ダイアログの JS が壊れない |
| AC-9 | 削除ボタンは `button.danger` で赤く表示され、接続テスト・編集と視覚的に区別できる |
| AC-10 | 参照チェックのロジックに単体テストがある |
| AC-11 | `./gradlew test` が通り、detekt が既存ベースライン 84 件のままである |

## 6. 制約事項

| ID | 制約 |
|---|---|
| C-1 | `ConfigSource` インターフェースは変更しない。参照チェックは既存の `listTables` + `sharedJdbcRefOf` の組み合わせで行う |
| C-2 | 参照チェックのロジックは DB に依存しない純粋な関数として切り出し、TDD で書く |
| C-3 | 削除ボタンは `form` + `POST` で実装する（既存方針） |
| C-4 | 確認メッセージの生成は #8 の `DeleteConfirm` に寄せる。JS エスケープを 2 箇所に書かない |
| C-5 | 接続文字列を画面に出す場合は必ず `ConnectionStringMasker` を通す（既存方針） |
| C-6 | `deleteSharedJdbcConfig` 自体の挙動は変更しない。参照チェックはルート側で行う |

## 7. 影響範囲

| 対象 | 影響 |
|---|---|
| `web/views/ConnectionsView.kt` | 操作列に削除ボタンを追加。削除不可時の表示を追加 |
| `web/views/DeleteConfirm.kt` | データソース用の確認メッセージを追加 |
| `web/routes/ConnectionsRoutes.kt` | 削除ハンドラに参照チェックを追加 |
| `config/` | **変更なし**（C-1） |
| `docs/` | 永続的ドキュメントへの影響なし（基本設計・データモデルの変更を伴わない UI 追加のため） |

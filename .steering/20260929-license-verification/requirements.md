# ライセンス状態の実検証 — 要求定義

| 項目 | 内容 |
|---|---|
| 開発タイトル | license-verification |
| 対応 Issue | [#31](https://github.com/sugimomoto/KintoneExternalAppCDataSample/issues/31) |
| 作成日 | 2026-09-29 |
| 経緯 | [#12](https://github.com/sugimomoto/KintoneExternalAppCDataSample/issues/12) の実機確認で発見 |
| 目的 | ライセンスが実際に使える状態かを画面で分かるようにし、コンテナでの認証手順を確立する |

---

## 1. 背景

### 1.1 事象

`adapter-console` コンテナ内でストアドプロシージャを実行できない。

```
このシステム上には、CData JDBC Driver for Salesforce 2025J用のライセンスが
インストールされていますが、ライセンス認証されていない状況です。
[コード：I nodeid：11111111]
```

にもかかわらず、**ドライバー画面は 4 本すべて「有効」と表示している**。

```
cdata.jdbc.bcart.jar         | cdata.jdbc.bcart.BCartDriver        | 有効
cdata.jdbc.googlesheets.jar  | cdata.jdbc.googlesheets.GoogleSh... | 有効
cdata.jdbc.salesforce.jar    | cdata.jdbc.salesforce.Salesforce... | 有効
cdata.jdbc.sapgateway.jar    | cdata.jdbc.sapgateway.SAPGateway... | 有効
```

### 1.2 原因

`.lic` ファイルの**有無だけ**で判定している。

`jdbc/JdbcDriverManager.kt:85`

```kotlin
licenseStatus = if (licPath.exists()) LicenseStatus.ACTIVATED else LicenseStatus.NOT_ACTIVATED
```

CData のライセンスはマシン（nodeid）に紐づくため、`.lic` があっても
**別マシンで認証されたものなら使えない**。コンテナはホストとは別マシンと判定される。

### 1.3 調査で判明した事実

| # | 事実 | 詳細 |
|---|---|---|
| F-1 | ライセンスチェックの厳しさが**機能ごとに違う** | 下表 |
| F-2 | ホストでは Salesforce の `sys_procedures` が読める | `GetOAuthAuthorizationUrl` 等を取得できた |
| F-3 | コンテナでは 4 本すべて `sys_procedures` が読めない | 「ライセンス認証されていない状況」 |
| F-4 | Google Sheets はホストでも期限切れ | 「試用ライセンスの有効期間が切れています [コード：J]」 |
| F-5 | ライセンスエラーのメッセージは**ロケール依存** | 日本語で返ってきた。#19 と同じ理由でパースしない方針を採る |
| F-6 | 非対話のアクティベーション実装が既にある | `jdbc/DriverActivator.kt` が `java -jar X.jar -l` に stdin を流す |

コンテナ内で実測した機能別の可否:

| 操作 | 結果 |
|---|---|
| `sys_connection_props` の SELECT（接続フォームのプロパティ一覧） | ✅ 動く |
| `DatabaseMetaData.getTables()`（`list-tables`） | ✅ 動く（SAP 64 件 / BCart 18 件） |
| **`sys_procedures` の SELECT** | ❌ ライセンス認証されていない |
| OAuth 認可ウィザード (#12) | ❌ 上記に依存するため使えない |

### 1.4 課題

1. **画面が実態と違う** — 「有効」と出ているのに機能が使えない。原因調査の入口を誤らせる
2. **コンテナでの認証手順が無い** — README はホストでの `java -jar X.jar -license` を案内している
3. **ホストとコンテナで `.lic` を共有している** — `lib/` をマウントしているため、
   どちらか一方でしか認証できない可能性がある

## 2. ユーザーストーリー

- **セットアップ担当者として**、ライセンスが実際に使える状態かを画面で知りたい。
  「有効」と出ているのに機能が動かないと、どこを調べればよいか分からない。

- **セットアップ担当者として**、コンテナでライセンスを有効にする手順を知りたい。

- **セットアップ担当者として**、ライセンスの検証で勝手にライセンスファイルが
  書き換わったりしないでほしい。

## 3. 受け入れ条件

### 3.1 状態の検証

- [ ] **AC-1** ライセンスが実際に使える状態かを検証できる
- [ ] **AC-2** 検証結果に生のエラーメッセージが含まれ、原因が読み取れる
- [ ] **AC-3** 検証はロケール依存のメッセージをパースしない（有効/無効の 2 値で判定する）
- [ ] **AC-4** 検証がライセンスファイルを書き換えない
- [ ] **AC-5** 検証で外部への実通信が発生しない

### 3.2 表示

- [ ] **AC-6** ドライバー画面で「`.lic` がある」と「実際に使える」を区別して表示する
- [ ] **AC-7** 検証は明示的な操作で行う（画面表示のたびに全ドライバーへ接続しない）
- [ ] **AC-8** 検証に失敗したドライバーで何をすべきか分かる

### 3.3 ドキュメント

- [ ] **AC-9** コンテナでのアクティベーション手順が README にある
- [ ] **AC-10** ホストとコンテナで `.lic` を共有する際の注意が書かれている
- [ ] **AC-11** 機能ごとのライセンス要件（1.3 の表）が書かれている

### 3.4 品質

- [ ] **AC-12** 検証結果の判定にユニットテストがある
- [ ] **AC-13** `./gradlew test` が通り、本変更で lint の指摘が増えない

## 4. 制約事項

| # | 制約 | 理由 |
|---|---|---|
| C-1 | エラーメッセージをパースして分類しない | ロケール依存（F-5）。#19 で同じ判断をしている |
| C-2 | 検証で `.lic` を書き換えない | 検証と認証は別操作。検証のつもりでライセンスが変わると困る（AC-4） |
| C-3 | 検証で外部通信しない | `Offline=true` を付けたプローブ接続を使う（AC-5） |
| C-4 | 画面表示のたびに全ドライバーへ接続しない | ドライバー画面が重くなる（AC-7） |
| C-5 | `.lic` の有無判定は残す | 「ファイルが無い」と「ファイルはあるが使えない」は別の情報 |

## 5. スコープ外

| 項目 | 扱い |
|---|---|
| **コンテナ内でのアクティベーション実行** | 手順のドキュメント化までとする。実行は利用者が判断する。`lib/` はホストと共有しているため、`.lic` の書き換えはホスト側の動作に影響しうる |
| Google Sheets の期限切れライセンスの更新 | 利用者の契約の話 |
| ライセンスチェックが機能ごとに違う理由の解明 | CData 側の実装。観測した事実（1.3 の表）を記録するに留める |
| 実データのクエリに対するライセンス要件の検証 | 接続先の資格情報が必要で、OAuth 未認可の接続では確認できない |

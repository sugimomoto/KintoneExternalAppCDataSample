# データソース一覧の堅牢性改善 — 要求定義

| 項目 | 内容 |
|---|---|
| 開発タイトル | connections-list-robustness |
| 作成日 | 2026-09-29 |
| Issue | [#39](https://github.com/sugimomoto/KintoneExternalAppCDataSample/issues/39), [#40](https://github.com/sugimomoto/KintoneExternalAppCDataSample/issues/40) |
| 目的 | データソース一覧画面が壊れた設定で落ちないようにし、接続テストを画面遷移せずに実行できるようにする |

2 件をまとめて扱う。どちらも `/connections` 一覧の同じ描画経路 (`connectionRow`) に手を入れるため、
別作業にすると同じ箇所を 2 度触ることになる。

---

## 1. 背景

### 1.1 現状の実装

| 箇所 | 内容 |
|---|---|
| `web/views/ConnectionsView.kt` `connectionsListView` | 行ごとに `ctx.configSource.loadSharedJdbcConfig(name)` を呼ぶ |
| `web/views/ConnectionsView.kt:100` `connectionRow` | 接続テストが `form` + `POST`。削除は #36 で追加済み |
| `web/routes/ConnectionsRoutes.kt:166` `POST /connections/{name}/test` | **HTML 断片**を `respondText` で返す（レイアウトなし） |
| `web/routes/ConnectionsRoutes.kt:183` | 失敗時は `result.exceptionOrNull()?.message` を**生のまま**出す |
| `web/views/Layout.kt:40` | htmx を読み込み済み (`/static/htmx.min.js`) |
| `web/views/DriversView.kt:182` | ライセンス検証が `hx-post` + `hx-target` で動く**お手本** |

### 1.2 課題

#### 課題 1: 壊れた設定行 1 つで一覧全体が 500 になる (#39)

`loadSharedJdbcConfig` は `config_json` を `JdbcConfig` にデシリアライズするため、
1 行でも JSON が壊れていると例外が伝播して**一覧画面全体が 500** になる。
正常な接続も一切表示されず、画面から復旧できない。

#36 の実機検証中に、手で入れた検証データのキー名を間違えて踏んだ。

```
kotlinx.serialization.MissingFieldException: Fields [driver-class, driver-jar] are required
  for type with serial name 'com.cdata.kintone.adapter.config.JdbcConfig', but they were missing
```

`config_json` はアプリが書くものだが、スキーマ変更・手動編集・書き込み中断で壊れ得る。
壊れた 1 行のせいで画面全体が使えなくなるのは影響が大きすぎる。

#36 で追加した削除拒否の経路も一覧を再描画するため、同じく 500 になる。

#### 課題 2: 接続テストが別画面に遷移する (#40)

ボタンが通常の `form` + `POST` なのに、ハンドラの応答は**既に HTML 断片**。
つまり**断片を返す API にフォーム送信しているミスマッチ**で、レイアウトの無い裸の断片が
ページとして表示される。一覧に戻るにはブラウザバックが必要で、続けて他の接続を
テストできない。

#### 課題 3: 失敗メッセージが未マスク (#40 に同梱)

`result.exceptionOrNull()?.message` を生で出しているため、例外メッセージに接続文字列が
含まれていた場合に**資格情報が画面に出る**。既存方針では画面表示は必ず
`ConnectionStringMasker` を通す。

## 2. 目的

- 壊れた設定行があっても一覧が表示され、画面から復旧できるようにする
- 接続テストを一覧に留まったまま実行できるようにする
- 失敗メッセージから資格情報が漏れないようにする

## 3. スコープ

### 3.1 今回実装する機能

| ID | 機能 | 対応 Issue |
|---|---|---|
| F-1 | 設定読み込みを行単位で失敗許容にする。読めない行は「読み込めません」と示し、他の行は正常表示 | #39 |
| F-2 | 読めない行にも削除ボタンを出す（画面から復旧できる導線を残す） | #39 |
| F-3 | 接続テストを htmx 化し、結果を行内に表示する | #40 |
| F-4 | 実行中であることを示す | #40 |
| F-5 | 失敗メッセージを `ConnectionStringMasker` でマスクする | #40 |

### 3.2 今回実装しない機能 (スコープ外)

| 項目 | 理由 |
|---|---|
| `config_json` のスキーママイグレーション | 壊れ方が一通りではない。まず画面が落ちないようにする |
| 壊れた行の自動修復 | 何が正しい値かはアプリには分からない |
| 連携一覧 (`/syncs`) の同種の問題 | 別画面・別経路。影響を確認してから別途対応する |
| 未保存のフォーム値での接続テスト | ハンドラの KDoc が実態と合っていないだけ。コメント修正に留める |
| `ErrorMessageTranslator` による接続エラーの分類 | ロケール依存メッセージは分類しない方針（#19） |
| 全画面での htmx 化の統一 | 本件は一覧の接続テストに限定する |

## 4. ユーザーストーリー

| ID | ストーリー |
|---|---|
| US-1 | デモ環境を構築する担当者として、設定が 1 つ壊れても一覧画面を開きたい。他の接続を確認・操作できなくなるのは困るため |
| US-2 | デモ環境を構築する担当者として、壊れた設定を画面から削除したい。DB を直接触らずに復旧したいため |
| US-3 | デモ環境を構築する担当者として、複数の接続を続けて接続テストしたい。1 件ごとにブラウザバックするのは手数が多いため |
| US-4 | デモ環境を構築する担当者として、接続テストが実行中かどうか分かるようにしてほしい。OAuth 接続はタイムアウトまで時間がかかることがあるため |
| US-5 | 環境を人に見せる担当者として、接続テストの失敗メッセージに資格情報が出ないでほしい。画面共有中に漏れるため |

## 6. 制約事項

| ID | 制約 |
|---|---|
| C-1 | `ConfigSource` インターフェースは変更しない。読み込み失敗の捕捉は呼び出し側で行う |
| C-2 | `loadSharedJdbcConfig` の挙動（壊れていれば例外を投げる）は変更しない。設定の読み込みが静かに失敗するのは危険 |
| C-3 | 接続テストの応答は今も HTML 断片のまま。htmx 側を合わせる（ハンドラの返却形式は変えない） |
| C-4 | 画面に接続文字列や例外メッセージを出す場合は必ず `ConnectionStringMasker` を通す |
| C-5 | htmx の使い方は `DriversView.kt` のライセンス検証に合わせる。同じ画面内で流儀を分けない |
| C-6 | 接続エラーメッセージは分類しない（#19 の方針）。マスクしてそのまま見せる |

## 7. 影響範囲

| 対象 | 影響 |
|---|---|
| `web/views/ConnectionsView.kt` | `connectionRow` の引数を変更。テストボタンを htmx 化。読み込み失敗の表示を追加 |
| `web/routes/ConnectionsRoutes.kt` | 接続テストの失敗メッセージをマスク。KDoc を実態に合わせる |
| `config/` | **変更なし**（C-1, C-2） |
| `resources/static/app.css` | 実行中表示のスタイルを追加する可能性あり |
| `docs/` | 永続的ドキュメントへの影響なし（基本設計・データモデルの変更を伴わない） |

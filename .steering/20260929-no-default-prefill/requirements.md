# 既定値を保存しない接続フォーム — 要求定義

| 項目 | 内容 |
|---|---|
| 開発タイトル | no-default-prefill |
| 対応 Issue | [#27](https://github.com/sugimomoto/KintoneExternalAppCDataSample/issues/27) |
| 作成日 | 2026-09-29 |
| 経緯 | [#11](https://github.com/sugimomoto/KintoneExternalAppCDataSample/issues/11) の実機確認で発見 |
| 目的 | 利用者が触っていないプロパティを接続文字列に保存しないようにする |

---

## 1. 背景

### 1.1 事象

データソース接続の作成フォームが、**ドライバーの既定値をそのまま接続文字列に保存する**。

保存済みの接続文字列（`shared_jdbcs.url_template`）とドライバーの既定値が一致している。

| プロパティ | ドライバーの既定値 | 保存された値 |
|---|---|---|
| `OAuthSettingsLocation` | `%APPDATA%\CData\GoogleSheets Data Provider\OAuthSettings.txt` | 同じ |
| `Pagesize` | `1000` | 同じ |
| `PoolMaxSize` | `100` | 同じ |
| `Verbosity` | `1` | 同じ |
| `IgnoreErrorValues` | `true` | `on`（同義） |

登録済み 5 接続のうち **4 件**が `OAuthSettingsLocation` を含む。

### 1.2 原因

| 箇所 | 内容 |
|---|---|
| `web/views/ConnectionsView.kt` `propertyField` | `value = currentValue ?: prop.defaultValue ?: ""` で**既定値を入力欄に埋める** |
| `web/routes/ConnectionsRoutes.kt` `buildUrlFromForm` | `prop.*` のうち空でない値を**すべて**連結する |

「利用者が設定した値」と「こちらが勝手に埋めた既定値」を区別できていない。

### 1.3 影響

1. **`%APPDATA%` が Linux コンテナに持ち込まれる**

   Windows 用の既定値がそのまま保存され、コンテナ内ではリテラル文字列のパスになる。
   OAuth トークンキャッシュとスキーマキャッシュの保存先が該当する。

2. **#11 の修正が効かない**

   #11 で OAuth キャッシュパスを接続単位に一本化したが、利用者の明示指定を
   尊重する仕様のため、既定値が保存されている接続では一本化が効かない。

3. **ドライバー更新で既定値が変わっても追従しない**

   保存時点の既定値が固定される。

4. **接続文字列が読みにくい**

   意味のある設定（認証情報・接続先）が既定値の羅列に埋もれる。画面のプレビューも同様。

### 1.4 調査で判明した事実

| # | 事実 | 詳細 |
|---|---|---|
| F-1 | 空値は既に保存対象外 | `buildUrlFromForm` が `isNotBlank()` で除外している。**埋めるのをやめれば保存されない** |
| F-2 | `#14` の条件解決は未入力を既定値で補う | `PropertyHierarchyResolver` の実効値は「入力値 → 無ければ `Default`」。未入力でも絞り込みは正しく動く |
| F-3 | 真偽値はチェックボックスで描画している | チェックボックスは「未指定」を表現できない。未チェック時は送信されない |
| F-4 | 選択肢つきプロパティには「-- 未指定 --」がある | `allowedValues` があるものは `<select>` で、空の選択肢を持つ |
| F-5 | 編集時は保存済みの値が入力欄に入る | `existingValuesOf` が保存済み URL を解析して渡す |
| F-6 | プール設定はドライバー由来ではない | `pool.*` は本アプリの設定。既定値の埋め込みは問題にならない |

---

## 2. ユーザーストーリー

- **接続を作る利用者として**、自分が入力していないプロパティが勝手に保存されないでほしい。
  ドライバーの既定値はドライバーに任せたい。

- **接続を作る利用者として**、未入力のときに何が使われるのか知りたい。
  空欄なら「既定値が使われる」と分かるようにしてほしい。

- **既存の接続を編集する利用者として**、保存済みの値は今までどおり表示・編集したい。

---

## 3. 受け入れ条件

### 3.1 保存内容

- [ ] **AC-1** 触っていないプロパティが接続文字列に含まれない
- [ ] **AC-2** 利用者が入力・選択したプロパティは保存される
- [ ] **AC-3** 既存の接続を編集して保存したとき、保存済みの値は維持される
- [ ] **AC-4** 新規作成した接続で #11 の OAuth キャッシュ一本化が効く

### 3.2 表示

- [ ] **AC-5** 未入力の欄で、ドライバーの既定値が何か分かる
- [ ] **AC-6** 真偽値プロパティで「未指定」を選べる
- [ ] **AC-7** 編集時は保存済みの値が入力欄に入る（デグレなし）
- [ ] **AC-8** 接続文字列プレビューに未入力のプロパティが出ない

### 3.3 既存機能への影響

- [ ] **AC-9** #14 の認証方式による絞り込みが未入力状態でも正しく動く
- [ ] **AC-10** プール設定 (`pool.*`) の既定値表示は変えない
- [ ] **AC-11** JDBC 接続文字列の直接入力は従来どおり優先される

### 3.4 品質

- [ ] **AC-12** 「未指定は保存しない」がユニットテストで固定されている
- [ ] **AC-13** `./gradlew test` が通り、本変更で lint の指摘が増えない

---

## 4. 制約事項

| # | 制約 | 理由 |
|---|---|---|
| C-1 | 既定値との一致判定で除外する方式は採らない | `IgnoreErrorValues` は既定値 `true` に対して `on` が送られる。表記揺れの正規化が必要になり、ドライバーごとの差異に追従できない。**送らせない**方が確実 |
| C-2 | 既存の保存済み接続文字列を自動で書き換えない | 意図して既定値と同じ値を入れた利用者と区別できない。編集して保存すれば落ちる |
| C-3 | 保存形式（`url_template`）は変えない | 構造化は波及範囲が大きい。本件の解決には不要 |
| C-4 | 直接入力欄は残す | プロパティ定義が取れないドライバーの逃げ道 (#15) |

---

## 5. スコープ外

| 項目 | 扱い |
|---|---|
| 保存形式の構造化（プロパティのマップ化） | C-3。`existingValuesOf` の URL 再解析をやめられる利点はあるが、本件とは独立 |
| 既存接続の一括移行 | C-2。`%APPDATA%` を含む接続の画面警告は別途判断 |
| 非 CData ドライバーでの挙動 | 今回は考慮しない（利用者判断） |

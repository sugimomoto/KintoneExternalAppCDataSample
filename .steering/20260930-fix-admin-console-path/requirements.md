---

## 1. 背景

### 1.1 課題

接続画面 (`/syncs/{name}/connect`) の Step 2 が案内するパスが誤っている。

| | パス |
|---|---|
| 現在の表示 | `https://<kintone ドメイン>/k/admin/system/admin/dataConnector.html` |
| 正しいパス | `https://<kintone ドメイン>/k/admin/system/externalapp/` |

実環境で確認された正しい URL は `https://cdatajapan.cybozu.com/k/admin/system/externalapp/`。
現在の案内どおりに開いても目的の画面にたどり着けない。

### 1.2 なぜ今まで気づかなかったか

誤ったパスは Phase 2-C の初期実装（`c0ff597`）から入っていた。

当時は「kintone 管理画面を開く ↗」リンクの `href` として使われていたが、#51 で判明したとおり
`KINTONE_DOMAIN` がコンテナに渡っておらず、`domain.isNotBlank()` が常に偽だったため
**このリンクは一度も表示されていなかった**。誤りに気づく機会がなかった。

#51 でリンクを「パスの案内表示」に置き換えた際、設計の制約 C-3 に
「管理画面のパスは現行の値を維持する」と書き、**値の正しさを検証しないまま引き継いだ**。
画面に出るようになって初めて誤りが表面化した。

### 1.3 教訓

「現行の値を維持する」という制約は、その値が正しいことを確認して初めて妥当になる。
表示されていなかった値を表示するようにした時点で、検証が必要だった。

## 2. 目的

Step 2 の案内が正しい管理画面のパスを示すようにする。

| ID | 制約 |

| C-1 | パスの値は**実環境で確認されたもの**を使う。推測しない |

| C-3 | #51 で決めた「ドメインを持たない」方針は変更しない |

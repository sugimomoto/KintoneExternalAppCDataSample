# 05. 機能・フィールド型・コネクター制約

「外部システムのアプリ化」機能（v1.0時点）の **kintone 側制約** の一覧。

出典：構築マニュアル `3.4 利用できるアプリ機能` / `3.5 利用できるフィールドタイプ` / `7 よくある質問`。

## kintone フィールド型の対応可否

外部システム接続したアプリでは、**ラベル・罫線・スペース・関連レコード一覧以外は、外部システム接続したフィールドのみ配置可能**。

| フィールド型 | 対応 | 補足 |
|---|---|---|
| レコード番号 | ○ | BIGINT 型カラムのみ指定可（NUMBER ID時）／TEXT ID 時は VARCHAR |
| 文字列（一行） | ○ | 自動計算・値の重複禁止は未対応 |
| 文字列（複数行） | ○ | |
| リッチエディター | **×** | |
| 数値 | ○ | 値の重複禁止は未対応 |
| 計算 | **×** | |
| ドロップダウン | ○ | 選択肢は Adapter で定義必要（SelectionFieldDefinition.options） |
| チェックボックス | **×** | |
| 複数選択 | **×** | （※protobufには MultipleSelectionField があるが kintone UI 側で未対応） |
| ラジオボタン | **×** | |
| 日付 | × | |
| 時刻 | × | |
| 日時 | ○ | 値の重複禁止は未対応 |
| 添付ファイル | **×** | |
| リンク | × | |
| ユーザー・組織・グループ選択 | × | |
| 関連レコード一覧 | ○ | |
| ルックアップ | ○ | コピー元フィールドにレコード番号・数値・計算フィールドは指定不可 |
| テーブル（サブテーブル） | **×** | |
| ラベル | ○ | |
| 罫線 | ○ | |
| スペース | ○ | |
| グループ | × | |
| 作成日時 | × | |
| 作成者 | × | |
| 更新日時 | × | |
| 更新者 | × | |

**実装に効く制約**：
- **日付単独・時刻単独は使えない** → DB の `DATE` 型はあえて `DatetimeField` に変換するか、kintone 側で「日時」で扱う必要あり
- **作成日時・更新日時・作成者・更新者が使えない** → Adapter 側で常に管理する必要があり、メタデータカラムは普通のカラムとして扱う
- **複数選択不可** → `MultipleSelectionField` は protobuf に存在するが kintone UI から使えないので、当面実装しても呼ばれない

## システム制約

| 項目 | 制約 |
|---|---|
| 1 ドメインあたりのコネクター数 | **最大 20** |
| 1 コネクターあたりの外部連携アプリ数 | 無制限（通常のアプリ数としてカウント） |
| 1 Adapter が扱えるテーブル数 | **1テーブルのみ** |
| 連携アプリは何コース利用可？ | **ワイドコースのみ** |
| Select の limit | 最大 501 |
| Search の limit | 最大 100 |
| Aggregate の limit | 最大 10001 |
| field_id 文字列長 | 1〜128 文字 |
| RecordId.value_text | 英数+_-、最大100文字 |

## サンプル Adapter 固有の制約

サンプル adapter のドキュメント・実装上の制約（CData 版でこれら制約を回避することが提供価値の一つ）：

| 項目 | 制約 |
|---|---|
| 対応 DB | Prisma がサポートする DB のみ（MySQL/PostgreSQL動作確認済） |
| 必須カラム | 名前が `id` の BigInt 型・ユニーク カラムが必要 |
| 対応する SQL 型 | Int, BigInt, Float, Double, TEXT, VARCHAR, DateTime |
| アクセス権 | レコード/フィールドのアクセス権なし |
| Search の対応 | コメントアウト（FULLTEXT インデックス前提） |
| Aggregate の対応 | 未実装 |

## スキーマ変更時の制約

> Q. kintone 接続後にデータベースのスキーマ定義を変更した場合どうなりますか？
>
> A. 変更したスキーマに合わせて、Adapter の定義を修正することで変更を反映できます。
>    ただし、既に外部システムに接続して作成したアプリで追加したカラムを利用する場合には、
>    自動的に「文字列（一行）」で追加され、ルックアップや文字列（複数行）には変更できません。
>    新規に外部システムに接続してアプリを作成すると、自由にフィールドタイプを選択できます。

→ **後からカラム追加すると、kintone 側のフィールド型は強制的に「文字列(一行)」になる**。これは UX 上の制約として認識し、ユーザーに事前説明する必要がある。

## CData JDBC 版 Adapter で意識すべき制約

1. **Salesforce / SAP / NetSuite 等の TEXT ID 対応 → `RecordIdType = TEXT` で宣言**
2. **数値の精度問題**：`DECIMAL(38, 10)` などは `NumberField` (double) に変換すると損失。要件次第で `TextField` フォールバック
3. **Aggregate 実装**：kintone 側のグラフ機能は対応しているので、SUM/AVG等を含む集計の SQL 化対応が望ましい
4. **接続プールの考慮**：1 Adapter = 1 テーブルだが、複数 kintone アプリから同時アクセスされうる → HikariCP 等で接続プール設計
5. **Driver ライセンス**：CData JDBC Driver はライセンスキー必要。OEM/ランタイムキーの調達計画が必要
